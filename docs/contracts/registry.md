# Реестр контрактов сервисов

Источник правды об интерфейсах сервисов монорепозитория `calculator-test-app`.
Контракт описывается **до** реализации и изменяется вместе с ней: изменение публичного
интерфейса без правки контракта считается дефектом.

| Сервис | Тип | Каталог | Контракт | Версия | Статус |
| --- | --- | --- | --- | --- | --- |
| `frontend` | Клиентское SPA (браузер) | `frontend/` | [frontend.md](./frontend.md) | 1.0.0 | реализован, тесты проходят |

## Границы монорепозитория

| Компонент | Состояние | Комментарий |
| --- | --- | --- |
| `frontend` | существует | единственный сервис миссии; содержит доменное ядро, UI и тесты |
| `backend` | **отсутствует** | сервис frontend самодостаточен: вычисления выполняются на клиенте, сетевых вызовов и серверного API нет |

Поэтому у сервиса `frontend` **нет внешних зависимостей-сервисов**: контракт не резервирует
ни одного сетевого интерфейса (HTTP, WebSocket, RPC), ни схемы данных, ни точки аутентификации.
Если серверное API когда-либо появится, оно оформляется отдельным сервисом и отдельным контрактом
в этом реестре; текущий контракт frontend при этом меняться не обязан.

## Внутренние (непубличные) интерфейсы

Перечисленные сущности намеренно **не** входят в контракт и могут меняться без согласования:

- модульная структура файлов внутри `frontend/src` (кроме перечисленных в контракте модулей);
- внутренние компоненты `Display` и `Keypad` считаются публичными только в объёме props и DOM-хуков;
- стили (`frontend/src/index.css`) — значения цветов, отступов, шрифтов;
- тестовые хелперы внутри `*.test.ts(x)`;
- содержимое `dist/` (артефакт сборки, в репозиторий не попадает).
